## User-visible changes and documentation impact

### 1. Role-based workflow progress sections ([#204](https://github.com/LemmaLegalConsulting/docassemble-WorkflowDocs/pull/204))

The standard percentage progress bar is disabled and replaced with named navigation sections in three workflows:

- **Assemble Documents**
  - Advocate: Select templates → Prepare documents → Complete requested information → Review and sign → Finish
  - External requestee: Review and sign → Complete requested information → Finish
- **Request Documents**
  - Advocate: Set up request → Send request → Track uploads
  - Client: Instructions → Upload documents → Finish
- **Send Questionnaire**
  - Advocate: Set up questionnaire → Send questionnaire → Await response
  - Client: Answer questions → Review responses → Finish

Current status: `src/pages/whats-new.md` announces the change, but links only two of the three affected workflows. The workflow guides do not explain or visually show the new sections.

### 2. Questionnaire delivery and configurable AI fields ([#205](https://github.com/LemmaLegalConsulting/docassemble-WorkflowDocs/pull/205))

The release:

- Correctly carries URL-serialized booleans and questionnaire setup values into the recipient session.
- Makes **Save responses to LegalServer?** govern the sent case note, completed case note, and supporting-document upload.
- Uploads client questionnaire documents to the LegalServer matter as a ZIP when saving is enabled.
- Lists uploaded filenames in the completed questionnaire case note.
- Attaches supporting documents to the advocate completion email when their combined size is at most 15 MB; larger sets get a session download link instead.
- Replaces individual AI field checkboxes with additive presets. The default is configurable per client with `questionnaire default ai field set`; configured custom fields join the parties-and-richer presets.
- Uses the selected preset only for advocate-facing suggested-question generation. `none` sends no matter fields and produces generic suggestions.
- Improves graceful handling of transient AI failures.

Current status: `docs/send-questionnaire.md` and `docs/admin-guide.md` cover nearly all of this. Two phrases need tightening: the case note contains a **filename list**, not the file binaries, and the files are uploaded separately to the matter. `src/pages/whats-new.md` says selected information is used for “AI-assisted follow-up questions,” but the preset actually controls advocate-facing **suggested questions**.

### 3. `fix_punctuation` for `ask` and `request` ([#206](https://github.com/LemmaLegalConsulting/docassemble-WorkflowDocs/pull/206))

Both filters accept `fix_punctuation=true` and apply Docassemble punctuation repair only to resolved string output. For `request`, repair runs only in a configured `expected_key` render pass (normally `final`), avoiding interference with question gathering and placeholders. Undefined and non-string values are left unchanged.

Current status: this is already covered in `docs/template-variables.md`, `docs/request-filter.md`, and `src/pages/whats-new.md`. No new page is needed. The existing table in `docs/template-variables.md` should be clarified so `default` and `hint` do not appear to be accepted by `request` after the preceding sentence correctly says they are not.

## Recommended edits

### Priority 1 — Correct and complete the release summary

**File: `src/pages/whats-new.md`**

1. Add `Request Client Documents` to the progress-section links.
2. Replace “selected case information for AI-assisted follow-up questions” with “selected case information for advocate-facing suggested questions.”
3. Make questionnaire delivery concrete: supporting documents can be uploaded to the LegalServer matter and attached to the advocate email, with a download-link fallback above 15 MB.
4. Keep the entry audience-focused; do not expose the internal boolean parser or exception-handling implementation.

### Priority 2 — Explain the new progress UI in each affected workflow

**Files:**

- `docs/assemble-documents.md`
- `docs/request-documents.md`
- `docs/send-questionnaire.md`

Add a short “Progress sections” note near the start of each guide. List the advocate and client/requestee sequences shown above and explain that the active section changes with the person’s role. This prevents users from expecting the former percentage bar and makes screenshots/walkthrough steps easier to reconcile with the product.

If a v1.5.6 environment is available, replace or supplement the first screenshot in each guide with a screenshot that includes the section navigation. Capture both advocate and client/requestee navigation only where the layouts differ meaningfully. Use descriptive alt text and crop out matter/client identifiers.

### Priority 3 — Tighten questionnaire result semantics

**File: `docs/send-questionnaire.md`**

1. In “What the Advocate Receives,” distinguish the three outputs:
   - HTML summary email;
   - attachments when total size is ≤15 MB, otherwise a secure session download link;
   - completed case note containing the conversation and a list of uploaded filenames;
   - supporting files uploaded separately as a ZIP to the LegalServer matter.
2. State explicitly that these LegalServer writes occur only when **Save responses to LegalServer?** is on and usable LegalServer launch data is present.
3. Clarify that the AI field preset affects initial suggested-question generation, not client answers, follow-up analysis, or the data displayed to the client.
4. Add a troubleshooting item for missing email attachments: combined uploads above 15 MB are intentionally linked instead.

### Priority 4 — Clarify the template-filter option table

**File: `docs/template-variables.md`**

Split the current shared options table or add an “Accepted by” column. Mark `default` and `hint` as `ask`-only, and `placeholder`/`expected_key` as `request`-only. Retain the existing `fix_punctuation` example and link to `docs/request-filter.md` for render-pass details.

No substantive change is needed in `docs/request-filter.md`; it already accurately documents resolved strings, `expected_key`, placeholders, undefined values, and non-string values.

### Priority 5 — Confirm administrator reference remains source-aligned

**File: `docs/admin-guide.md`**

Retain the existing `questionnaire default ai field set` reference and example. During final review, verify:

- default: `case_information`;
- accepted values: `none`, `case_information`, `case_information_and_parties`, `case_information_and_parties_and_notes`, `everything`;
- invalid configured values fall back to `case_information`;
- configured LegalServer custom fields are included only for parties-and-richer presets.

No separate documentation is recommended for `wfd_parse_bool` or transient AI exception recognition because these are internal reliability fixes without a user-facing configuration or workflow choice.

## Validation checklist

1. Compare all behavioral claims against the v1.5.6 tagged source and tests, not only the release prose.
2. Run `npm run typecheck`.
3. Run `npm run build` to catch broken links, invalid MDX, and missing images.
4. Check the generated `/whats-new` page and all five edited guides at desktop and narrow widths.
5. Verify the 15 MB boundary wording is **at most 15 MB attaches; over 15 MB links**.
6. Verify every named progress section exactly matches the labels in v1.5.6.
7. Verify the release entry links all three workflows affected by #204.
8. If screenshots are updated, confirm they came from v1.5.6 and contain no client or matter data.

1. Correct `src/pages/whats-new.md`.
2. Add progress notes to the three workflow guides.
3. Tighten questionnaire delivery and AI-preset wording.
4. Clarify the filter option matrix.
5. Add screenshots if a safe v1.5.6 environment is available.
